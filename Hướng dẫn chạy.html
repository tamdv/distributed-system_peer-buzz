Hướng Dẫn Chạy Hệ Thống PeerBuzz

Bài tập lớn môn học: Các Hệ Thống Phân Tán (Chủ Đề 3 - P2P Chat)

⚙️ 1. Chuẩn bị môi trường

Trước khi chạy hệ thống, hãy cài đặt môi trường tương ứng cho thiết bị của bạn:

Bootstrap Server (Cài đặt Dart SDK)

Trên Máy macOS:

Cài đặt qua Homebrew:

bash 
brew tap dart-lang/dart
brew install dart

Trên Máy Windows:

Cài đặt qua Winget hoặc Chocolatey:

cmd 
winget install Dart.Dart
cmd 
choco install dart-sdk

Kiểm tra phiên bản sau khi cài đặt:

bash 
dart --version

Peer Client (Cài đặt ứng dụng PeerBuzz)

Ứng dụng khách đã được đóng gói sẵn cho các hệ điều hành, cài đặt nhanh chóng:

  • macOS (PeerBuzz-macos.dmg):

    Mở file .dmg và kéo biểu tượng PeerBuzz vào thư mục Applications để sử dụng.

  • Windows (PeerBuzz-windows.zip):

    Giải nén thư mục và chạy trực tiếp file peerbuzz.exe để khởi động ứng dụng.

  • Android (PeerBuzz-android.apk):

    Copy file .apk vào điện thoại Android và tiến hành cài đặt trực tiếp.

  • iOS (PeerBuzz-ios.ipa):

    Cài đặt thông qua TestFlight, các công cụ ký chứng chỉ bên thứ 3 hoặc cài qua Xcode.

Mẹo mạng LAN: Để các Peer trên thiết bị khác nhau (ví dụ: máy tính và điện thoại) có thể kết nối trực tiếp, tất cả phải kết nối vào cùng một mạng Wi-Fi hoặc mạng nội bộ LAN.

🖥️ 2. Khởi chạy Bootstrap Server

Bootstrap Server đóng vai trò hỗ trợ Peer Discovery (quản lý danh sách online và trả về các địa chỉ IP:Port đang hoạt động).

  1. 1 Di chuyển vào thư mục server:

    Mở terminal và di chuyển đến thư mục chứa Bootstrap Server.

    bash 
    cd bootstrap_server
  2. 2 Tải các thư viện phụ thuộc:

    Cập nhật dependencies cần thiết cho Dart project.

    bash 
    dart pub get
  3. 3 Khởi chạy server:

    Mặc định server sẽ chạy trên cổng 8888 lắng nghe tất cả các card mạng.

    bash 
    dart run bin/bootstrap_server.dart

    Khi chạy thành công, màn hình console sẽ hiển thị:

    output 
    ==============================================
🚀 PeerBuzz Bootstrap Server is running
📍 Address: 0.0.0.0:8888
⏱  Timeout policy: 60s
==============================================

    Minh họa quá trình khởi chạy Bootstrap Server

📱 3. Khởi chạy và Kết nối Peer Client

Bước 3.1: Xác định địa chỉ IP của Bootstrap Server

Để các Client có thể kết nối tới Server, bạn cần tìm địa chỉ IP nội bộ (Local IP) của máy tính đang chạy Bootstrap Server:

Trên máy chủ macOS:

Mở Terminal và gõ lệnh sau để lấy IP:

bash 
ipconfig getifaddr en0
# Hoặc xem trong Cài đặt hệ thống > Wi-Fi / Mạng
Trên máy chủ Windows:

Mở Command Prompt (cmd) và gõ lệnh:

cmd 
ipconfig

Tìm dòng IPv4 Address của card mạng đang kết nối (ví dụ: 192.168.1.X).

Bước 3.2: Cài đặt và Đăng nhập Client

  1. 1 Khởi chạy ứng dụng:

    Mở ứng dụng PeerBuzz đã cài đặt trên hệ điều hành tương ứng ở Bước 1.

  2. 2 Nhập thông tin kết nối tại màn hình Đăng Nhập:
    • Tên hiển thị: Nhập tên tùy chọn của bạn (ví dụ: Peer_740).
    • Bootstrap Server Address:

      Nhập địa chỉ máy chủ theo định dạng: [IP_Bootstrap]:[Port]

      • Nếu chạy Client trên cùng một máy với Server: Nhập 127.0.0.1:8888.
      • Nếu chạy Client trên thiết bị khác trong cùng mạng LAN: Nhập địa chỉ IP tìm thấy ở Bước 3.1 kèm cổng 8888 (ví dụ: 192.168.1.18:8888).

    Giao diện nhập địa chỉ Bootstrap Server trên ứng dụng Peer Client

  3. 3 Tham gia mạng:

    Ấn nút Tham gia mạng để bắt đầu quá trình khám phá Peer và tham gia kết nối chat.

🧪 4. Kịch bản kiểm thử (Demo Scenarios)

Để kiểm chứng đầy đủ các tính năng phân tán nâng cao, hãy thực hiện kịch bản thử nghiệm sau:

Kịch bản 1: Chat nhóm & Đồng hồ Lamport

  1. Mở 3 client song song (ví dụ: Peer A, Peer B, Peer C).
  2. Cả 3 cùng vào mục Chat Nhóm (Broadcast).
  3. Gửi tin nhắn liên tục và quan sát thứ tự tin nhắn. Nhờ cơ chế Đồng hồ Lamport (Lamport Clock), tin nhắn sẽ được sắp xếp đồng bộ về mặt thời gian logic trên cả 3 máy.

Kịch bản 2: Ngoại tuyến & Lưu trữ hộ (Store-and-forward)

  1. Peer A đang chat với Peer B.
  2. Tắt kết nối mạng hoặc tắt hẳn ứng dụng Peer B (Peer B offline).
  3. Peer A gửi tin nhắn cho Peer B. Do mất kết nối trực tiếp, ứng dụng của Peer A sẽ tự động tìm kiếm một láng giềng đang online khác (ví dụ Peer C) và gửi yêu cầu storeFor.
  4. Peer C sẽ lưu trữ tạm thời tin nhắn này.
  5. Mở lại Peer B online. Peer C phát hiện Peer B hoạt động trở lại từ danh sách cập nhật của Bootstrap, sau đó tự động chuyển tiếp (forward) các tin nhắn đang lưu giữ cho Peer B.

Kịch bản 3: Gossip-down phát hiện sự cố nhanh

  1. Khi Peer B đột ngột ngắt kết nối (không gửi gói leave chủ động).
  2. Peer A thử gửi tin nhắn đến Peer B và thất bại (socket timeout).
  3. Peer A sẽ ngay lập tức lan truyền gói tin gossipDown báo cáo Peer B offline cho các node láng giềng khác để cập nhật giao diện ngay lập tức mà không cần đợi Bootstrap Server quét timeout (60 giây).
